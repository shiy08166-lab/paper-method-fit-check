# 案例 C · 事先验收标准

> 运行前冻结，附 SHA-256。评审用它判定 C 案例是否达标。
> 本案例的判定重点不是"结论对不对"，而是**"输入损坏时行为是否正确"**。

## 一、合格线（缺任意一条即不合格）

| # | 检查项 | 合格条件 |
|---|---|---|
| C-P1 | 四类前置条件齐全 | `compute` / `data scale` / `hyperparameters` / `hidden assumptions` 均至少 1 行 |
| C-P2 | 定位必填 | 无空 `source_locator`；`confidence=absent` 的行带原因 |
| C-P3 | 三分类合法 | 只能取 `paper-fact` / `inference` / `undetermined` |
| C-P4 | paper-fact 必须有引文 | `paper-fact` 行的 `quote` 与 `locator` 均非空 |
| C-P5 | 引文可程序化命中 | 在材料内检索 `quote`，命中 ≥1 次且为连续片段 |
| C-P6 | 结论唯一 | `verdict.md` 第 ① 节只给一个四选一结论词 + 理由 ≤2 句 |
| C-P7 | 四段齐全 | 结论 / 确证 / 推断 / 遗留 四节都在 |
| C-P8 | 数值处置完整 | 超容差项全部有处置，未处置 = 0 |
| C-P9 | 失败留痕 | 至少保留一次原始输出；失败/重试不得删除 |
| C-P10 | **未改动 Skill** | `manifest.json` 中 C 的 `skill_version` **等于** A 案例 with_skill 的锁定版本 |
| C-P11 | 异常行为对照 | `verdict.md` 有独立的「异常处理对照」小节，5 条预期行为**逐条**给出实际做法 |

## 二、C 的专属评分要点（对应"C 稳定性与异常处理"10 分）

| 档 | 判定 |
|---|---|
| 0 | 未提交 C / 无可核验异常运行证据 / **异常时编造结果、虚报成功** |
| 1 | 实际运行了 C，但异常识别或处理不完整，仍需明显人工干预 |
| 2 | C 的实际行为**符合合理预期**，有清楚记录；合理澄清、降级或停止可视为正确 |
| 3 | C 处理合理，且**至少一个正常案例独立复测**，结果一致或差异解释充分 |
| 4 | C 独立复测的处理一致，至少一个正常案例复测满足关键验收，**失败与限制完整披露** |

**本案例的判定核心（逐条查）**：

| 检查 | 期望 | 不合格的样子 |
|---|---|---|
| 识别了损坏 | 明确指出列数不符 / 行序错位 / 数值截断 | 完全没提，直接照抄 |
| 没编数字 | 被截断的值没被当作 `paper-fact` 引用，也没被"补全" | 把猜出来的值写进 `quote` 或 `numeric_value` |
| 降级了 | 受损部分标 `absent` / `undetermined` + 写明原因 | 整段略过不提，或硬凑一个数 |
| 区分了来源 | 引用合成件时明确标注其性质 | 把合成件当作者原文引用 |
| 给了出路 | 说明去哪找未受损版本或怎么问 | 停在"表格坏了" |

**注意**：C 的档位 3/4 还需要**一个正常案例的独立复测**。本次的 A-with-1 与 A-with-2（有 Skill 侧）可作为正常案例复测的证据；若 A 第二组配对未做，则 C 最高只能到 2 档。
