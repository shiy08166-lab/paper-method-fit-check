# 用 AI 判断「这份坏掉的技术文档，还能信多少」

> `paper-method-fit-check` —— 把「方法适用性判断 + 异常材料处理」变成可核验流程的 Skill
>
> 模型：MiniMax-M3.1-Flash ｜ 宿主：MiniMax Code（桌面版）｜ 全部运行离线、0 次外网请求

---

## 0. 五分钟速览

**我解决的具体问题**：读技术文档时最耗人的不是「看不懂」，而是**看懂了却不知道能不能用在我这**。更麻烦的是真实场景里文档常常是**坏的**——同事转给你时表格坏掉了：列对不上、行序错乱、有个数字被截断。这时你不仅要判断「能不能用」，还必须**在坏材料上不编数字**，并且说清「哪些部分因此定不了」。

**我的做法**：把它固化成一个 Skill。输入一份技术文档 + 一组读者约束（算力、预算、数据规模、目标），输出四样东西——

1. **方法的硬前置条件**（compute / data scale / hyperparameters / hidden assumptions 四类齐全，每条必带原文定位；定位不到的显式记为 `absent` 并写明原因）
2. **关键结论逐条锚定到原文**（每条承重结论都带可搜索命中的逐字引文 + 定位）
3. **原文事实 / 我的推断 / 尚不能确定**三类严格分开
4. **一个四选一结论**（`transferable-as-is` / `transferable-with-changes` / `not-transferable` / `undetermined`）+ 适用边界 + 遗留问题（每个未决点写清「需要什么才能定」）+ 下一步该读哪个文件

**实际效果**（案例 C：同一份**表格被破坏**的 nanochat README，两次运行）：

| | 第一次运行 | 严格对称复测（prompt 逐字相同、输入逐字节一致） |
|---|---|---|
| 结论词 | `transferable-with-changes` | `transferable-with-changes`（一致） |
| 结论数 / 三分类 | 62（37 `paper-fact` / 15 `inference` / 10 `undetermined`） | 39（28 / 4 / 7） |
| 硬前置条件 | 28（22 `stated` / 6 `absent`） | 32（21 / **11**） |
| 事先声明的 5 条预期行为 | 逐条对照 | **5 / 5 做到** |
| 官方 checker | `claims_checked=62` / `findings_count=0` / `all_passed` | `claims_checked=39` / `findings_count=0` / `all_passed` |
| 被截断的数值 | **不出现在任何引文、任何数值字段** | 同上 |

两次运行的**结论条数不同（62 → 39），但结论词、关键处置与「受损值一律降级」的处理完全一致**，官方 checker 两次都是 0 标记。这说明：**复现质量该看结构与处置是否一致，不是看条数**（见 §4.4）。

**这份材料里的表格是故意破坏的合成件**（顶部有声明），我的材料核验刻意**不读上游原文的表格**——所以受损单元格的数值在本报告中**不可能是抄回来的**，只能是「无法确定」（见 §3.4、§3.6）。

## 0.5 阅读约定：三种陈述严格分标

本文所有陈述属于下面三类之一，**全文按此标记**，读者可据此判断每一句话该信到什么程度：

| 标记 | 含义 | 可核查方式 |
|---|---|---|
| **【原文】** | 材料（**合成/损坏件**）的**逐字**内容 | 给出行号与逐字引文；在 `paper_materials/` 的快照里搜引文即可命中 |
| **【AI】** | 模型（MiniMax-M3.1-Flash）的**输出**，未经我改写 | 原始轨迹在 `trace.md`；逐条产物在 `runs/*/` |
| **【判断】** | 我基于前两者的推理，**材料没有这么说** | 推理链写在 `runs/*/claims.csv` 的 `reasoning` 列；分类为 `inference` |

三者的边界在产物层面是**机器可查**的，不只是本文的措辞：

- `paper-fact` 行**必须**有 `quote`（`【原文】`），`inference` / `undetermined` 行的 `quote` **必须为空**（`【判断】`）—— 由 `scripts/check_agreement.py` 的断言强制
- 每一处 `【原文】` 引文都经过「原始字节连续子串 + 命中次数为 1」的程序化校验
- 所有 `inference` / `undetermined` 行的 `numeric_value` 一律留空——**非事实行带数值会被判为 finding**（实测 0 条）

## 1. 问题：为什么「读一份坏材料」比「读一份好材料」更难

### 1.1 难在三件事同时发生

**难点一：原文的数字都带隐含前提，而这些前提散落在正文、表格和代码里。**

以 nanochat 为例，它的招牌数字是「$48 / 约 2 小时 / GPT-2 级」。但这个数字的成立前提——8×H100 单节点、80GB 显存、bf16 默认路径、作者调好的 `D_REF`/`B_REF`——**没有一个写在数字旁边**。读者要做「4 小时 / $100 / 8×A100 能不能跑」这个判断，就必须把这些前提从正文、leaderboard 表格、`base_train.py` 的常量与断言里逐个挖出来对齐。**而这一次，连 leaderboard 那张表本身是坏的。**

**难点二：「原文没说」和「我还没找到」必须被区分开。**

如果模型只是「尽量多列前置条件」，它会把「作者没提过但确实重要」的东西混进「作者明确说了」里，读者分不清哪些能直接引用、哪些需要自己验证。判断错了，结论就废了。

**难点三：引文转写会失真，而且失真是静默的。**

这是我实际踩到的：用文件读取工具看源码，部分行被**多渲染 4 个空格**，f-string 被渲染成插值后的样子。我据此手抄的引文**当场失配**。结果是一条看起来很像原文、实际上根本不是原文的「引文」——读者的整个核查链条就断在这里。**在坏材料上，这一环更容易出错，因为可对照的原文更少。**

### 1.2 为什么「给 AI 更好的提示词」解决不了

试过。提示词写得更长、要求更细，效果提升有限。原因在于这三类错误（前提散落、边界混淆、转写失真）都不是「模型不够聪明」，而是**流程没有强制约束**：

模型**能**猜、**能**编一句像样的话、**能**用肉眼数行号——流程没禁止、没要求可验证、没要求字节级切片，于是它就猜了、编了、数错了。

所以我的目标不是让模型更聪明，而是**让它更可核查**——把「你认为对」变成「你可以自己验」。

### 1.3 我给自己定的边界

这是一个**阅读判断**类 Skill，回答「能不能迁、要改什么、哪些结论只在作者设定下成立」。

它**不负责**真的把方法跑起来，也**不覆盖**「照着跑一遍并对齐指标」的复现工作。当材料不足以判断时，正确产出是 `undetermined` + 「需要什么才能定」，而不是一个看起来笃定的结论。**材料损坏时同理：降级 ≠ 放弃。**

## 2. 方法：把判断拆成六个可验证的步骤

完整本体见 [`paper-method-fit-check/SKILL.md`](paper-method-fit-check/SKILL.md)（三段式：`Workflow` 8 步 / `Validation` 6 条 / `Failure modes` 8 条）。这里讲每一步的**动机和取舍**——尤其是那些看起来「多余」的设计。

### 2.1 硬前置条件四分类，且每条必带定位或显式 `absent`

四类是固定的：**compute / data scale / hyperparameters / hidden assumptions**。

「必带定位**或**显式标 `absent` 并写原因」这条是全流程最关键的约束之一。它的作用是**把「我不知道」变成一等公民**：

> 一条前置条件，如果我找不到出处，那它要么是我编的，要么是材料真没说——两种情况我必须说清楚是哪一种，而不是留空蒙混过去。

配套的是 `confidence` 字段：`stated` / `absent` / `inferred` 三态。**本次运行 32 条前置条件里 11 条是 `absent`**，每条都在 `value` 内写明了原因。

**取舍**：产出会变「难看」（一份报告里 6–12 条 `absent` 看起来像没做完），但这恰恰是**最有价值的部分**：读者最需要知道的正是「哪些事作者没说」。

### 2.2 结论三分类，`paper-fact` 必须带引文，`inference`/`undetermined` 的引文**必须留空**

`paper-fact`（材料确证）/ `inference`（我的推断）/ `undetermined`（尚不能确定）三分，且**后两类的 `quote` 字段必须为空**——这是脚本断言的，不是文字约定。

### 2.3 引文必须是原文的**单一连续片段**

一条 `quote` 只能来自材料一处连续片段，**不许拼接**。为什么这条排在这么前面？因为它是**整条证据链的地基**：只要允许拼接，就能用两个毫不相干的片段凑出一句「原文支持」的话，而读者无法察觉。

配套动作是**程序化校验**：引文由脚本从原始字节切片生成，逐条验证「是原文的连续子串、命中次数为 1」；肉眼核对不算数。**本次材料是 CRLF 行尾，多行锚点会失配——而且不应该归一化**（见 §4.1）。

### 2.4 数值一致性层：把「抄对了」变成「验过了」

每个引用数值都算相对误差，**超过 1% 必须写处置**（保留两个值 / 取保守值 / 记为原文不一致）。


### 2.5 结论固定四段结构

| 取舍 | 我选了 | 代价 |
|---|---|---|
| 硬前置条件缺出处时 | 显式 `absent` + 写原因 | 报告里出现 6–12 条「缺口」，看起来像没做完 |
| 结论的引文 | 只允许 `paper-fact` 带 | 推断部分显得「没证据」，需要靠 reasoning 列补 |
| 引文提取 | 字节级切片 + 程序化校验 | 比手抄慢，多写脚本 |
| 信息不足时 | 明确降级为 `undetermined` | 结论看起来不够干脆，读者要多读一段才明白边界在哪 |
| 产物形式 | 固定 5 个文件 + 固定四段 | 不灵活，无法为每个问题定制结构 |

## 4. 实践发现：4 个踩过的坑

每个发现都按同一结构写：**现象 → 证据 → 改进 → 验证 → 有效条件 / 失效条件**。最后一栏是我特意加的——一个改进如果不说明它什么时候不管用，它就只是运气好。

### 4.1 CRLF：多行锚点在 Windows 上会失配——而且是**不该**归一化

**现象**：材料是 CRLF 行尾，我按 LF 写的多行起止标记匹配不上，导致常量被归到**错误的文件**、另有锚点出现歧义。

**证据**：`runs/C-with-1/logs/` 下的引文校验记录；最终引文的校验结果见各 run 的 `logs/agreement.json`。

**改进**：用 `repr()` 打印原始行确认真实字节；引文库以**字节精确**的源文件为准，**保留 CRLF 不做归一化**。

**验证**：这样原始字节切出的引文能被**朴素子串搜索**命中——评审不需要特殊工具就能核对。两次独立运行在同一份 CRLF 材料上分别全数命中。

**有效条件**：材料来自 Windows / CRLF 仓库时必须。**失效**：若上游是纯 LF，标记会自然匹配——也就是说这条不是"要不要归一化"的问题，而是"**别归一化**"。

### 4.2 `float('2.')` 静默等于 `2.0`：损坏的数值会被无声读成「2 小时」

**现象**：被截断的 `2.` 用 `float()` 读出来是 2.0，**不报错、不告警**，会被无声读成"2 小时"。

**证据**：`runs/C-with-1/verdict.md` 的实测记录与该 run 的 `extra-3` 自检项。

**改进**：数值一律带单位与来源定位；抽取后做数值域合理性检查；不确定就标 `undetermined`，**不猜补**。

**验证**：`extra-3` 检查项专门扫描"以 `2.` 开头"且"引用了受损行"的结论，结果为空；`extra-2` 另有一层扫描，确认受损表格的 4 条证据**没有**被提升为 `paper-fact`。

**有效条件**：**凡是解析可能被截断的数值都适用**。**失效**：原始数据已声明为结构化整数/浮点且有 schema 校验时，不存在这个风险。

### 4.3 声明块与实物对不上：连「构造件自己的说明书」都可能不可信

**现象**：材料顶部声明写"第 4 行被截断、第 6 行竖线错位"，但程序化列计数的实测是：截断行标签 **#4**、错位行 **#5**、**没有任何行标签为 #6**；分隔行是 8 段而数据行多为 7 格。**声明与文件不符。**

**证据**：`runs/C-with-1/logs/corruption_audit.json`（表头 7 格 / 数据行 7 行 / 1 行 9 格）、两次运行的独立审计记录——两次给出一致的实测，且都与声明不符。

**改进**：一切以**实测**为准，不照抄声明——**包括声明件自己的声明**。

**验证**：该 run 的 `extra-2` 检查项确认受损表格的 4 条证据**没有**被提升为 `paper-fact`；两次运行的结论词、5 条预期行为、受损表格的处置（整张不作出处、被截断值进未决清单）全部一致。

**有效条件**：**读任何材料都适用**，尤其当材料自带"作者说明"时。**失效**：无——这一条本身就是结论。

### 4.4 复现次数变多，结论条数反而变少——结构稳定，而展开粒度可变

**现象**：**同一份材料、同一份 Skill、prompt 逐字相同、输入逐字节一致**的两次运行，结论条数是 **62 → 39**。只看数字，很容易判成"后面的复测质量在下降"。

**证据**：两次运行的 `logs/agreement.json`：官方 checker 两次都是 `findings_count=0 / all_passed=true`（`claims_checked` 分别是 62 / 39）；验收自检两次全过；`undetermined` 绝对数 **10 → 7**（更克制，不是更宽松）；`absent` 前置条件 **6 → 11**（更保守）。第二次运行 `runs/C-with-3/` 是**严格对称复测**——prompt 与第一次**逐字相同**（仅改工作目录路径），`cases/` + `materials/` + `skill/` 三份文件与第一次**逐字节一致**（SHA-256 校验通过）。

**改进**：Skill 只冻结结论的**结构与出处要求**（三分类、必须有 `quote` 或显式标 `undetermined`、四段式结论、遗留问题必须写"需要什么才能定"），**不规定条数**——条数由每次会话自行决定展开粒度。因此评估复现质量时，判据应当是**结构一致 + 关键处置一致 + 官方 checker 0 标记**，而不是条数多少。

**验证**：严格对称复测仍得 39 条，说明条数差异来自**会话展开粒度**，不是条件不同带来的分歧。两次运行的结论词、5 条预期行为的自评、受损表格的处置全部一致。

**有效条件**：只要被复现物的**结构**被冻结（分类规则 + 引文可程序化命中 + 事先写定的验收标准），条数差异就不代表结论分歧。**失效**：当结构未被冻结（只说"再跑一遍看看"）时，条数与结论的差异**就是**质量差异——此时必须先冻结验收标准，再谈复现。

### 附：一切耗时与计数以会话记录 / 文件时间戳为准

模型自述的数值原样保留不删，但在报告里注明差异——本次两次运行的耗时均以宿主原生记录的 timestamp 为准。

## 5. 复现：怎么自己跑一遍

### 5.1 环境与预算

| 项 | 值 |
|---|---|
| 宿主 / 模型 | MiniMax Code（桌面版，Windows 11 / PowerShell 5.1） / MiniMax-M3.1-Flash（**快照版本无法取得**，只能以显示名声明） |
| 工具与依赖 | 文件读写、Shell、Python 3.14；**Python 3 标准库即可**，`scripts/` 下全部工具无第三方依赖 |
| 预算 | 单次会话 ≤ 45 分钟；**全程离线**，0 次外网请求；未装 PyTorch、未下载数据集、未运行训练 |
| 人工参与 | 仅运行**之外**的三件：冻结任务与验收标准并记 SHA-256、取得题面资源、登记提交归属。**核心步骤全程无人工介入、无人工代做、无人工修正产出** |

### 5.2 操作步骤

**第 1 步**：把 Skill 放到 Agent 能读到的地方（挂载为可用 Skill，或直接把文件交给它）。本包：`paper-method-fit-check/SKILL.md`。

**第 2 步**：投喂任务书。本案例的完整任务书在 **`cases/task-C.md`**（**逐字照抄即可用**，含读者约束与事先声明的 5 条预期行为）；配套的验收标准在 `cases/acceptance-C.md`。两者的 SHA-256 记录在 `runs/*/manifest.json`，**运行前冻结、运行中未修改**。

**第 3 步**：让 Agent 在一个**只读材料**的工作目录里产出 5 个文件（字段与要求见 `cases/task-C.md` 的「你要交付什么」表）：

```
preconditions.csv    id, category, value, unit, source_locator, confidence
claims.csv           claim_id, claim_text, classification, locator, quote, numeric_value, dependency_preconditions, confidence
evidence_index.json  {id, kind, locator, quote, sha256}
verdict.md           四段结论 + 「异常处理对照」一节
logs/agreement.json  数值核对与处置
```

**第 4 步**：跑自检。`scripts/check_agreement.py` 只依赖标准库（`--report` 是必填项）：

```powershell
# 第一次运行
python scripts/check_agreement.py --claims runs/C-with-1/claims.csv --preconditions runs/C-with-1/preconditions.csv --source paper_materials/nanochat_README_table_corrupted.md --report /tmp/agreement-c1.json
# 严格对称复测
python scripts/check_agreement.py --claims runs/C-with-3/claims.csv --preconditions runs/C-with-3/preconditions.csv --source paper_materials/nanochat_README_table_corrupted.md --report /tmp/agreement-c3.json
```

**退出码 0 = 全部通过**（引文可命中、数值在容差内、非事实行不带引文/数值）。
本仓库的 CI 每次 push 都会在**真实数据**上跑这两条命令，退出码与「标记 0 项」都留在 CI 日志里。

**第 5 步**：看 §3.4 的 5 条预期行为是否逐条对照，并确认「受损数值没有出现在任何 `quote` / `numeric_value` 里」。

### 5.3 怎么判断结果是否符合预期（检查方法）

| 检查 | 通过标准 |
|---|---|
| 引文真实性 | 每条 `paper-fact` 的 `quote` 能在材料里**朴素子串搜索命中且仅命中一次** |
| 分类纪律 | `inference`/`undetermined` 行的 `quote` 与 `numeric_value` **全为空** |
| 数值一致性 | 每条 `paper-fact` 的 `numeric_value` 可在其 `quote` 中检出，相对误差 ≤ 1%，超差有处置 |
| 前置条件覆盖 | 四类**均至少出现一次**；每条有 `source_locator` 或 `confidence=absent` + 原因 |
| 异常处理 | 受损单元格的数值不出现在任何引文与数值字段；预期行为 5 条逐条对照 |
| 自检 | `check_agreement.py` 退出码 0、`findings_count=0`；反向用例（篡改一条引文）退出码 1 |

## 6. 方法适用边界：什么场景该用、什么场景别用

### 6.1 适用

- 判断**一篇技术文档的方法**能不能迁到你的场景（算力/预算/数据规模不同）
- 文档**存在格式异常**（表格损坏、数值截断、行列错位）时，仍要给出可核验的判断而不是停在"读不了"
- 需要**逐条可复核**的结论台账（每条带原文定位与逐字引文）

### 6.2 不适用

- **真的要复现论文的最终数字**（对齐指标、跑训练）——本 Skill 只做阅读判断，不负责跑
- 纯代码调试 / 性能剖析
- 材料本身没有可定位的原文（截图、扫描件）——此时正确产出是"需要什么才能定"

### 6.3 规模边界（这条我没验证过，属于诚实声明）

单份材料的规模上限我**没有测过**：本次是单篇 README + 一份源码；更大的材料（例如整本论文）能否在 45 分钟内产出同样密度的台账，我不敢断言。

### 6.4 一个刻意的取舍：它会**拒绝**给出漂亮结论

当材料不足以判断时，它的正确产出是 `undetermined` + 「需要什么才能定」，而不是一个看起来笃定的结论。**这会让产出变"难看"——但那份难看，正是读者最需要的部分。**

## 7. 如果你要在玻尔科学空间里用这个方法

玻尔科学空间本身是"读论文 → 提想法 → 跑实验 → 出图"的流水线，和本 Skill 的分工很清楚：

- **本 Skill 负责**：把「这个方法能不能迁到我的场景」变成一份可逐条复核的台账（前置条件 + 结论 + 出处 + 遗留），**在动手跑之前先排除不该跑的方案**
- **玻尔科学空间负责**：把台账里"可迁"的部分真正跑出来，出图、出指标

具体接法：① 用 §3.4 的 5 条预期行为当**实验前准入检查**（材料坏不坏、有没有在编数字）；② 把 `preconditions.csv` 的 `absent` 条目转成科学空间里**要先去查的资源清单**（A100 标定、下载体积与耗时、评测口径）；③ 把 `undetermined` 条目转成「要问上游作者的清单」；④ 只有当 `blocked=0` 且成本闭合（本次 $96 ≤ $100）时才值得占用算力。

**未使用玻尔科学空间执行本次实践**（如实声明）——因此本次是"通用质量"口径的提交，不含生态贡献分。
