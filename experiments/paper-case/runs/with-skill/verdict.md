# 迁移判定：LoRA 论文 → 24GB 单卡 + 7B 场景

## 1. Verdict

**transferable-with-changes**

论文的 LoRA 机制（冻结预训练权重、注入低秩 A/B 矩阵）在原理上适用于任意含稠密层的网络，与模型规模无关，因此方法可以迁移到 7B。但论文从未在 7B 模型或 24GB 消费级显卡上实验，读者必须自行选定具体配置（bf16、只调 Wq/Wv、小 rank、梯度检查点、限制序列长度）并本地验证质量与吞吐。

## 2. What is established（论文确证，带定位）

以下均为 `paper-fact`，有原文页码定位与逐字引文，详见 `claims.csv` 与 `evidence_index.json`。

- 机制：LoRA 冻结预训练权重并注入可训练的低秩分解矩阵（ABSTRACT, PAGE 1，PF-1）；原理适用于任意稠密层（§4, PAGE 4，PF-10；§8, PAGE 12，PF-11）。
- 参数与显存收益：相对 GPT-3 175B + Adam 全量微调，可训练参数量降 10,000 倍、GPU 显存需求降 3 倍（ABSTRACT, PAGE 1，PF-2/PF-3）；GPT-3 175B 训练显存从 1.2TB 降到 350GB（§4.2, PAGE 5，PF-4）；r=4 且只调 Wq/Wv 时 checkpoint 从 350GB 降到 35MB（§4.2, PAGE 5，PF-5）。
- 吞吐：GPT-3 175B 上 LoRA 训练吞吐 43.1 tokens/s/V100，全量微调 32.5（fn 5, PAGE 5，PF-7）；正文称 25% 加速（§4.2, PAGE 5，PF-6）。
- 公式与默认配置：可训练参数量公式 |Θ| = 2 × L̂LoRA × dmodel × r（§5.1, PAGE 6，PF-8）；大多数实验只调 Wq、Wv（§5.1, PAGE 6，PF-12）；GPT-3 的两个预算 4.7M / 37.7M（§D.4, PAGE 20，PF-13）；GPT-3 用 AdamW、2 epoch、batch 128、weight decay 0.1、序列长度 384/768/2048（§D.4, PAGE 19-20，PF-14/PF-15）。
- 低 rank 有效性：r=1 或 2 即足够，即便满秩 d 高达 12,288（INTRODUCTION, PAGE 2，PF-9）。
- 覆盖的模型规模：RoBERTa base 125M / large 355M（§5.2, PAGE 7，PF-23）、DeBERTa XXL 1.5B（§5.3, PAGE 7，PF-21）、GPT-3 175B（§5.5, PAGE 8，PF-22）。注意：论文没有 7B 规模实验。
- 数据与低数据：论文在 100 / 1k / 10k 的低数据子集上验证（§F.3, PAGE 22，PF-16），该区间 LoRA 优于或可比全量微调（§F.3, PAGE 22，PF-17）。
- 局限：小 rank 在跨语言下游任务上可能不如全量微调（fn 6, PAGE 10，PF-18）；模型规模与最优 rank 的关系仍是开放问题（§H.2, PAGE 24，PF-19）；部署时可用 W = W0 + BA 合并，无额外推理延迟（§4.1, PAGE 4，PF-20）。

## 3. What I inferred（我的推断，不是论文说的）

以下均为 `inference`，引文与 `numeric_value` 已按硬性要求留空，推理在 `claims.csv` 的 `reasoning` 列。这些结论明确不是论文原文。

- INF-1：机制可迁移到 7B。依据 PF-10/PF-11（方法适用于任意稠密层）与 PF-21（除 GPT-3 外最大实验模型仅 1.5B）。这是从逐层低秩分解机制推出的推断，论文没有 7B 实测。
- INF-2：7B 全量微调放不进 24GB，LoRA 放得进。算式：全量微调 ≈ (2+2+4+4)=12 字节/参数 × 7e9 = 84GB > 24GB；LoRA 冻结底座 7e9×2=14GB(bf16)，只训练 |Θ|=2×64×4096×8=4.19M（假设 Llama-2-7B 的 dmodel=4096、L=32、只调 Wq/Wv、r=8），优化器+梯度≈4.19M×12≈50MB，合计约 14.05GB + 激活，需梯度检查点并限序列长度。参数来源：PF-8（公式）、PF-3/PF-4（论文 GPT-3 显存下降，方向性）；模型规格与每参数字节数是假设。
- INF-3：7B 上 r=1..8 只调 Wq/Wv 的可训练参数量约 0.52M..4.19M，与论文 GPT-3 的小预算 4.7M 同量级。依据 PF-8 公式与 PF-13。
- INF-4：8,000 条英文标注样本落在论文已验证的数据区间（100/1k/10k/392K，E2E ~42k），且同语言，跨语言限制不适用。
- INF-5：7B LoRA 在 8k 样本上约需单卡数小时、远低于 $200 预算。仅启发式：43.1×(175/7)≈1078 tokens/s（V100 量级）× 假设 4090≈1.3×V100 ≈1400 tokens/s；工作量 8000×384×5=15.36M tokens → ≈3 小时。175/7 与 1.3× 都是我的假设，不是论文数据。

## 4. What remains open（未定 + 缺失前置条件，及如何补）

以下为 `undetermined` 与 `absent` 前置条件，均写明「需要什么才能定 / 去哪找」。

- UND-1：LoRA 在 7B 上能否追平全量微调质量。论文无 7B 实验。需本地小实验或外部 LoRA-on-7B 研究。
- UND-2：7B 在 24GB 卡上含激活的精确显存。论文唯一绝对显存数字是 GPT-3 175B。需用所选 7B 模型和序列长度跑内存 profiling（PyTorch max_memory_allocated / transformers Trainer）。
- UND-3：RTX 4090 上 7B 的精确吞吐与租卡费用。论文只有 V100/GPT-3 数字。需真实 4090 短 benchmark。
- UND-4：7B 的最优 rank 与调哪些权重矩阵。论文 rank 研究在 GPT-3/GPT-2，且自述规模与最优 rank 关系开放（PF-19）。需在读者任务上做 r=1,2,4,8,16 扫描。
- UND-5：论文的精确倍数（3× 显存、10,000× 参数、2/3 VRAM）在 7B 上是否成立。这些是 GPT-3 口径；机制可迁移但倍数不保证（INF-2/INF-3 已用带假设算式估计）。
- 缺失前置条件（`preconditions.csv` 中 confidence=absent）：P-A4 论文无 7B 实验；P-A5 无 24GB 单卡显存测量；P-A6 无 RTX 4090 / bf16 实测。三者分别对应 UND-1/UND-2/UND-3，需按上面方式补测。

**核对时发现的论文自身不一致（如实写入，不抹平）：**

- 摘要称显存需求降「3 times」（PF-3），但 §4.2 的具体数字 1.2TB → 350GB 意味着 1200/350 ≈ 3.43×，不是精确的 3×。
- §4.2 正文称「25% speedup」（PF-6），但脚注 5 的吞吐 32.5 → 43.1 tokens/s 意味着 43.1/32.5 ≈ +32.6%，与 25% 对不上。

这两处不影响结论方向（都是方向性收益、数值略有出入），但属于原文自身的前后不一，故在此记录而非挑一个数当作唯一口径。

**下一步阅读/验证（优先于跑训练）：**

- 最高影响缺口是 UND-2/UND-3（24GB 上 7B 的显存与吞吐）。首选动作不是读论文，而是用 1 个 batch 在所选 7B 模型上做内存/吞吐 profiling；其次查该 7B 模型官方微调文档与社区 LoRA-on-7B 报告（如 Llama/ Mistral 微调指南）核对 rank、序列长度与 batch 的可行组合。
