### 找到了什么

作者侧把报告里引用的**每一个数字**从论文原文重新算了一遍（21 条账本 + 3 条语义检查，
一键 `python scripts/verify_paper_results.py` → `status: passed`）。
结论分两类：

1. **机械检查全绿，但语义不成立**——而且这次错在**论文自己身上**：
   论文第 5 页正文写「we also observe a 25% speedup」，
   同一页的脚注 5 却给 `32.5 tokens/s per V100 GPU`（全参微调）对
   `43.1 tokens/s per V100 GPU`（LoRA）；按吞吐提升的常规读法是 **+32.6%**。
   报告逐字引了这条脚注，**却没有把它和正文的 25% 对上**；
   官方 checker 对此**零标记**——它验的是「引文里的数 == 你写的数」，
   从不验「这个数是不是从论文自己的别的数推出来的」。
   同类问题还有「VRAM 降 2/3」「GPU memory by 3 times」，
   而论文自己的例子是 `1.2TB → 350GB`（= 3.43× / 70.8%）。
2. **压平表格的行列身份**：PDF 抽取文本把表格压成一串单元格，
   表 1 的 `|Θ|` 行是 **adapter 层**的参数量（0.5M/11M/11M），
   表 12 的 5 个行标签与它们的值被拆成两块（`128` 其实是 Batch Size）。
   作者侧靠 PDF 坐标重建（`scripts/extract_tables_geom.py`）才拿到真值——
   **这一步目前不在 Skill 里**。

### 对方法本身的改进建议

1. 给 SKILL 加第 7.5 步「**复算论文自己的算术**」：对每个比率/降幅，找出它依赖的基线数，
   用论文自己给的数重算，对不上就写进「遗留」。
2. 加一条纪律「**相对降幅必须配绝对量**」：`3×` 不能直接当「24GB 单卡能跑 7B」的依据。
3. 加一条纪律「**表格数字必须先确定行列身份**，确定不了就降级为 `undetermined`」。
4. 给「**否定性断言**」要求可核验证据：报告写「未发现论文自身有不一致」时，
   必须在 evidence_index 里登记它查过哪些位置，否则降级——
   **否定性断言目前完全不受任何机械约束**。

## ④ 真问题，以及它对「方法适用性核查」这一方法本身的改进建议

### ④.1 真问题（一句话）

> **论文第 5 页正文说「25% speedup」，同一页脚注 5 的两个数（32.5 → 43.1 tokens/s）
> 推出的是 +32.6%；报告把这两个数都逐字引了、官方 checker 零标记，
> 却既没有指出论文自身口径不一致，还写下了一句「未发现论文摘要与正文、正文与脚注互相矛盾的数字」
> ——这个否定性断言是错的，而且没有任何机械检查能发现它。**

具体三层：

| 层 | 事实 |
|---|---|
| 论文 | p.5 正文 `We also observe a 25% speedup`；p.5 脚注 5 `32.5 tokens/s per V100 GPU` → `43.1 tokens/s per V100 GPU`。`43.1/32.5−1 = +32.615%`。 |
| 机械检查 | 引文逐字命中 ✅；`numeric_value` 与引文内数字一致 ✅；`check_agreement.py` 标记 0 ✅；退出码 0 ✅。 |
| 语义 | 报告的 `PF10` 引了脚注 5 的两个数，`verdict.md` 的「预期行为对照 ②」却写「未发现论文摘要与正文、正文与脚注互相矛盾的数字」。**报告的否定性断言为假。** |

附带第二处同类问题：报告的 `PF2` 写「GPU memory 3x」（逐字引自摘要），
`PF8` 写「1.2TB→350GB」（逐字引自正文）——两条都是 paper-fact，
但报告没有把 `1200/350 = 3.43×` 和「3×」对上。

### ④.2 为什么现有的方法抓不到

- `check_agreement.py` 验的是三件事：引文是不是原文的**连续子串**、paper-fact 有没有 locator、
  `numeric_value` 在引文里找不找得到。**它不做任何跨引文的算术交叉核对。**
- SKILL v1.1 的第 7 步名字就叫「Run the numeric agreement check」，
  语义是「引文 ↔ 你写的数」，不是「论文自己说的数之间自洽吗」。
- 更关键的是：**「未发现不一致」这类否定性断言，在整个流程里没有任何对应的检查位**。
  模型说它查过了，机械层面拿不出任何证据证明它真查过。

### ④.3 五条改进建议（可直接写进 SKILL 的下一版）

| # | 建议 | 落点 | 验收标准 |
|---|---|---|---|
| 1 | **新增第 7.5 步「复算论文自己的算术」**：对每个比率/降幅/百分比，找出它在论文里依赖的基线数，重算一遍；对不上（差异超过 1%）必须写进 verdict 第 ④ 段 | SKILL.md 第 7 步之后 | 报告里每个百分比旁边有「复算：算式 = 结果」的字段；≥1 处差异被写进第 ④ 段 |
| 2 | **「相对降幅必须配绝对量」**：凡「省 X 倍 / 降 Y%」的迁移结论，必须同时给出基线的绝对值与单位，并算出落到读者场景后的绝对数 | SKILL.md 第 5 步（评估可迁移性） | 每条涉及数量的迁移结论都带一条绝对量算式 |
| 3 | **「表格数字必须先确定行列身份」**，确定不了就降级为 `undetermined`；并把「PDF 抽取文本会压平表格」写进 Failure modes | SKILL.md 第 3 步 + 第 4 步 | 引用表格数字的行/列写在 locator 里；无法确定的行没有出现在 paper-fact 里 |
| 4 | **否定性断言要求可核验证据**：凡结论形如「论文没有给出 X」「未发现不一致」，必须在 evidence_index 里登记**查过哪些位置/关键词**，否则降级为 `undetermined` | SKILL.md 第 4 步 | 每条否定性断言能指向一组「查过但没找到」的定位 |
| 5 | **把「按 PDF 坐标重建表格」作为可选工具进包**（`scripts/extract_tables_geom.py` 的最小版），或至少在任务书里要求会话自己重建行列身份 | SKILL.md 第 3 步 + `scripts/` | 表格类结论的行列身份有一份可复现的重建产物 |

### ④.4 这条发现对「有/无 Skill 对照」的含义

对照跑完后的观察写在 `comparison.md`。**先说结论方向**（详见该文件）：
**两轮都没有发现论文自身的口径不一致**——也就是说，
**这条错误不在「有没有 Skill」的差别里，而在方法本身的缺位**。
这正好说明对照实验的价值：它把「Skill 能做什么」和「方法缺什么」分开了。
